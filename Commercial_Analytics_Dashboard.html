What this suite does

One connected pipeline — not four disconnected exercises

Built on prescriber-level Rx data (CMS Part D schema): HCPs are segmented into four tiers by volume and brand loyalty → segments drive a capacity-constrained call plan that protects top-tier coverage first → actual call plan output feeds a fairness-audited incentive compensation model → call activity plus simulated marketing exposure feeds a channel-effectiveness regression to guide next quarter's non-personal promotion budget.

How the allocation logic works

Priority-ranked, capacity-constrained

Each of the 39 reps is assigned ~130 HCPs by territory. Target visit frequency is set by tier (Champion = 6/qtr, Growth = 3/qtr, Maintain = 1/qtr, Low-Priority = 0). Within a rep's fixed 200-call capacity, HCPs are served in tier-priority order, so a capacity-constrained rep under-serves Maintain-tier HCPs before ever touching a Champion or Growth account.

Insight: the plan is capacity-honest — it shows exactly where coverage breaks first, which is the deliverable a client actually needs (not a plan that pretends unlimited rep time exists).

Methodology: synthetic dataset built to the real CMS Medicare Part D Prescribers-by-Provider-and-Drug schema (NPI, specialty, state, drug, claims, cost) so the pipeline runs unchanged against the real file. Segmentation: K-means (scikit-learn). Call plan: capacity-constrained greedy allocation (Python). Incentive comp: quota = potential × growth target, 3-tier payout curve (Python + Excel model with live formulas). Marketing mix: standardized multiple linear regression (scikit-learn).
